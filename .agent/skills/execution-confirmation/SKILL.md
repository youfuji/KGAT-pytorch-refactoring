# 実行前ユーザー確認プロトコル

**コードの変更・コマンドの実行など、あらゆる実行アクションの前に、必ず以下のプロセスを踏むこと。**

## 基本ルール

1. **計画を先に提示する**: コード変更やコマンド実行を行う前に、実行計画（何を、どこに、どう変更するか）をユーザーに提示する
2. **フィードバックを反映する**: ユーザーからの修正要求があれば、計画を更新して再提示する
3. **明示的な承認を待つ**: ユーザーが「実行して」等の明確な承認を出すまで、実行に移らない
4. **承認なしに実行しない**: 計画提示後、ユーザーの応答を待たずにコードを変更してはならない

## ワークフロー

```
1. ユーザーからリクエストを受ける
       ↓
2. 調査・分析を行う（ファイル読み込み、コード理解等）
       ↓
3. 実行計画を作成し、ユーザーに提示する
   （implementation_plan.md を作成し、notify_user で確認を依頼）
       ↓
4. ユーザーのフィードバックを待つ
       ↓
  ┌─ フィードバックあり → 計画を修正して再提示（ステップ3に戻る）
  └─ 「実行して」等の承認 → ステップ5へ
       ↓
5. 承認済みの計画に基づいて実行する
```

## 実行計画に含めるべき内容

- **変更対象ファイル**: 修正・新規作成・削除するファイルの一覧
- **変更内容の概要**: 各ファイルに対して何をどう変更するか
- **影響範囲**: 他のファイルやモジュールへの影響
- **検証方法**: 変更後の動作確認の方法

## 注意事項

- 調査・分析（ファイルの閲覧、構造の確認）は承認なしで行ってよい
- **コード変更**（ファイルの書き込み・編集）は必ず承認後に行う
- 軽微な修正でも、実行計画の提示→承認のフローを省略しない
- ユーザーが「まとめて実行して」と指示した場合は、一括で実行してよい
